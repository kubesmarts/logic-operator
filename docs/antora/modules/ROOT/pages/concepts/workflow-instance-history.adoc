= Workflow Instance History
:description: Configure structured runtime events, Vector, and Data Index to query workflow history.

Workflow instance history is provided by Data Index. It is distinct from durable workflow
execution: runtime persistence stores state needed to continue active workflows after a restart,
while Data Index provides queryable execution history.

== Data path

. Quarkus Flow Runner emits structured workflow events to container logs.
. Vector tails container logs for its configured namespace and forwards recognized events to
  PostgreSQL.
. Data Index reads the stored events and exposes a GraphQL API.

Logic Operator configures the runtime logging environment and manages the Vector and Data Index
workloads. Data Index defines the GraphQL schema and event storage behavior.

== Requirements

Workflow history requires PostgreSQL, structured runtime logging, Vector, and Data Index. These
components are configured independently from runtime persistence; workflows can execute without
workflow history enabled.

Configure `LogicPlatform.spec.dataIndex.persistence.postgresql` for Data Index and enable
`dataIndex.vector`. Data Index's admission validation requires the Secret, Service, database name,
and database schema. Configure structured logging on the relevant `LogicFlowRuntime`:

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicFlowRuntime
metadata:
  name: hello-runtime
spec:
  logging:
    enabled: true
    includeWorkflowPayloads: false
    includeTaskPayloads: false
----

Keep payload logging disabled unless workflow input or output values are needed in history.
Payloads can contain sensitive data and increase log volume.

== Vector namespace filter

When `dataIndex.vector.watchNamespaces` is omitted, the admission webhook defaults it to the
LogicPlatform namespace. The current controller passes only the first list entry to Vector as an
exact namespace filter. Use one namespace name; wildcard values and multiple namespace filtering
are not currently supported.

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicPlatform
metadata:
  name: flow-platform
  namespace: workflows
spec:
  dataIndex:
    vector:
      enabled: true
      watchNamespaces:
        - workflows
----

== Query Data Index

Use the endpoint in `status.dataIndex.service.graphqlEndpoint`. For example, port-forward the
Data Index Service and query basic instance fields:

[source,bash]
----
kubectl port-forward svc/flow-platform-data-index 8080:80
----

[source,bash]
----
curl -X POST http://localhost:8080/graphql \
  -H 'Content-Type: application/json' \
  -d '{"query":"{ getWorkflowInstances(limit: 10) { id namespace name status startedAt endedAt } }"}'
----

See the https://kubesmarts.org/logic-apps/data-index/[Data Index documentation] for its current
GraphQL types, filters, and schema details.

== Troubleshooting

If instance history is empty, check that:

* the runtime has structured logging enabled;
* Vector watches the namespace where the runner pod is running;
* Vector and Data Index pods are ready;
* the LogicPlatform persistence Secret and Service references are valid; and
* the database is reachable and Data Index has completed its schema initialization.

The gateway can execute workflows without Data Index, but its `/v1/instances` endpoints return
`503 Service Unavailable` when the same-namespace LogicPlatform does not publish a Data Index
GraphQL endpoint. See xref:components/workflow-gateway.adoc[Workflow Gateway].
