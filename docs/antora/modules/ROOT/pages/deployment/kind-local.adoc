= Local Development with KIND
:description: Run Logic Operator on your laptop using a KIND cluster.

This is the developer and contributor path for building and running the source in a local Git checkout. Every `make kind-*` build uses the code and configuration in the currently checked-out branch, including local uncommitted changes; it does not install a published release. Choose the branch or commit you want to exercise before running the recipes.

For a published operator version on a cluster you manage, use xref:deployment/install.adoc[Installation options] and the xref:deployment/helm.adoc[Helm installation guide].

== Prerequisites

Install the following tools before starting:

* https://go.dev/dl/[Go] v1.26+
* https://docs.docker.com/get-docker/[Docker] v17.03+
* https://kubernetes.io/docs/tasks/tools/[kubectl] v1.30+
* https://kind.sigs.k8s.io/docs/user/quick-start/#installation[KIND] v0.20+
* https://kubectl.docs.kubernetes.io/installation/kustomize/[kustomize] (installed automatically by `make`)

== KIND Make targets

Run these targets from the repository root of your local clone:

[cols="1,3",options="header"]
|===
|Target |Purpose

|`make kind-create`
|Create the local cluster and install cert-manager and ingress-nginx.

|`make kind-deploy`
|Build the operator from the current checkout, load that image into KIND, and apply the manifests.

|`make kind-build-gateway`
|Build the gateway image from the current checkout and load it into KIND.

|`make kind-demo`
|Build/load the gateway and apply the sample workflow resources. Create and deploy the cluster first.

|`make kind-undemo`
|Remove the sample Logic Operator resources.

|`make kind-delete`
|Delete the local development cluster.
|===

The `kind-*` targets use the local KIND cluster named `logic-operator-dev` by default. They do not install the operator into a remote cluster. Run `make help` from the repository root to see the available target descriptions.

== Step 1: Create the Cluster

[source,bash]
----
make kind-create
----

This creates a KIND cluster named `logic-operator-dev` using `hack/kind-config.yaml`, then installs:

* ingress-nginx v1.12.2 (with ports 80 and 443 mapped to localhost)
* cert-manager v1.16.3 (required for webhook TLS)

The command is idempotent — if the cluster already exists it prints a message and exits cleanly.

[NOTE]
====
`lvh.me` is a wildcard DNS name that resolves to `127.0.0.1`.
All sample ingress hosts (e.g. `gateway.lvh.me`, `grafana.lvh.me`) work automatically without editing `/etc/hosts`.
====

== Step 2: Deploy the Operator

[source,bash]
----
make kind-deploy
----

This target:

. Builds the local operator source as `quay.io/kubesmarts/logic-operator:{operator-version}`
. Loads the image into the KIND cluster
. Applies `config/default` via kustomize with server-side apply
. Waits for all deployments in `logic-operator-system` to become available

The operator runs in the `logic-operator-system` namespace. Verify it is ready:

[source,bash]
----
kubectl get pods -n logic-operator-system
----

== Step 3: Apply Sample Resources

[source,bash]
----
make kind-demo
----

This applies `config/samples/` which creates:

* `LogicPlatform/logicplatform-sample` — manages the workflow gateway and its Ingress at `gateway.lvh.me`
* `LogicFlowRuntime/hello-runtime` — a stateless runner (defaults to the operator's Quarkus Flow Runner version, `{quarkus-flow-runner-version}-minimal` in this release)
* `LogicFlowDefinition/hello-world-v1-0-0` — the hello-world workflow

The gateway uses `LogicFlowDefinition.spec.runtimeRef` to route to the runtime's Kubernetes Service. A `LogicFlowService` is optional; when one exists, its `status.url` takes precedence and preserves its traffic policy.

Wait for the runtime pod to be ready, then invoke the workflow:

[source,bash]
----
kubectl wait --for=condition=available deployment/hello-runtime --timeout=120s
kubectl wait --for=condition=available deployment/logicplatform-sample-workflow-gateway --timeout=120s

curl -X POST http://gateway.lvh.me/v1/runtime/default/hello-world/1.0.0/sync \
  -H "Content-Type: application/json" \
  -d '{"name": "World"}'
----

Expected response:

[source,json]
----
{"message": "Hi, World!"}
----

== Troubleshooting: Webhook Not Ready

If `make kind-deploy` fails with a webhook connection error, cert-manager may not have issued the certificate yet.

[source]
----
Error from server (InternalError): ... connection refused
----

Wait a few seconds and retry:

[source,bash]
----
kubectl wait --namespace cert-manager \
  --for=condition=available deployment --all --timeout=120s

kubectl rollout restart deployment -n logic-operator-system
kubectl rollout status deployment -n logic-operator-system --timeout=120s
----

See xref:deployment/troubleshooting.adoc[Troubleshooting] for more common issues.

== Inspecting Resources

[source,bash]
----
# Check all Logic Operator CRs
kubectl get logicplatforms,logicflowruntimes,logicflowdefinitions

# Check runtime pod logs
kubectl logs -l app.kubernetes.io/name=hello-runtime -f

# Check operator logs
kubectl logs -n logic-operator-system -l control-plane=controller-manager -f
----

The runtime exposes health and OpenAPI endpoints through its internal Service. Start this port-forward in a separate terminal:

[source,bash]
----
kubectl port-forward svc/hello-runtime 8080:80
----

Then query it:

[source,bash]
----
curl http://localhost:8080/q/health
curl http://localhost:8080/q/openapi
----

== Next Steps: Persistence & Data Index

To test durable workflows and Data Index integration:

[source,bash]
----
# Apply PostgreSQL and LogicPlatform
kubectl apply -k config/samples/persistence/

# Wait for everything
kubectl wait --for=condition=available deployment/postgresql deployment/hello-runtime deployment/logicplatform-sample-data-index --timeout=120s

# Test a durable workflow
curl -X POST http://sleepy.lvh.me/ \
  -H "Content-Type: application/json" \
  -d '{"name": "local-test"}'

# Query Data Index GraphQL
GRAPHQL_ENDPOINT=$(kubectl get logicplatform logicplatform-sample \
  -o jsonpath='{.status.dataIndex.service.graphqlEndpoint}')

curl -X POST "$GRAPHQL_ENDPOINT" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "{ getWorkflowInstances(limit: 10) { id namespace name status startedAt endedAt outputData } }"
  }'
----

See xref:samples/persistence.adoc[Persistence & Data Index sample] for detailed documentation.

== Tear Down

Remove sample CRs without deleting the cluster:

[source,bash]
----
make kind-undemo
kubectl delete -k config/samples/persistence/ --ignore-not-found=true
----

Delete the entire cluster:

[source,bash]
----
make kind-delete
----
