= Production Checklist
:description: Production considerations for Logic Operator runtimes, platform components, and gateway access.

This page records configuration decisions to review before deploying Logic Operator in a
production cluster.

== Secure workflow endpoints

`LogicFlowRuntime.spec.security.type` defaults to `NONE`. Configure `API_KEY` or `OIDC` for
authenticated runtime endpoints, store credentials in Kubernetes Secrets, and restrict network
access to the runner Service.

The Workflow Gateway forwards authorization headers and responses to the runner and does not
define a separate authentication policy. Protect its Ingress or Route and configure runtime
authentication. The gateway can route workflows without a `LogicFlowService`.

== Configure persistence for durable execution

The default runtime image is the Quarkus Flow Runner `minimal` variant when persistence is
omitted. Workflows that must survive pod restarts need PostgreSQL persistence and the `standard`
runner image. The operator creates Lease coordination resources when persistence is configured.

* Use a production-grade PostgreSQL service.
* Keep runtime and Data Index schemas separate.
* Store credentials in a Secret and grant only the required database permissions.
* Use the standard runner image when overriding `LogicFlowRuntime.spec.image` for durable
  workflows.
* Configure `LogicFlowRuntime.spec.replicas` or an HPA targeting the `LogicFlowRuntime` CR. Do not
  target its Deployment directly, because the operator also reconciles the lease pool.

== Enable workflow history only when needed

Data Index and Vector are optional platform components. When Data Index is enabled, the admission
webhook requires PostgreSQL connection settings with Secret, Service, database, and schema. Vector
is configured independently under `dataIndex.vector`; workflow execution does not require either
component.

Vector currently receives a filter for only the first exact namespace in
`dataIndex.vector.watchNamespaces`. Omit the field to default to the LogicPlatform namespace. A
wildcard or multiple namespace entries are not supported by the current filter implementation.

Structured logging is configured on each runtime. Keep workflow and task payload logging disabled
unless it is required, since payloads may contain sensitive data and increase storage volume.

== Right-size workloads

Set requests and limits for the runner under `LogicFlowRuntime.spec.resources`. Use
`spec.podTemplate` for scheduling, sidecars, volumes, and pod-level settings; fields such as
`nodeSelector` and `imagePullSecrets` are directly under `podTemplate`, not under a nested `spec`.
Set resource requests for Data Index and Vector through their `application` settings.

== Horizontal Pod Autoscaling

=== LogicFlowRuntime

`LogicFlowRuntime` exposes a scale subresource. Target the CR itself so replica updates are
reconciled with the runner Deployment and, when persistence is configured, the Lease pool. The
admission webhook defaults `spec.replicas` to one; an HPA can subsequently update this field.

[source,yaml]
----
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: hello-runtime
  namespace: default
spec:
  scaleTargetRef:
    apiVersion: logic.kubesmarts.org/v1
    kind: LogicFlowRuntime
    name: hello-runtime
  minReplicas: 1
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
----

Durable persistence and leases coordinate active workflow instances across runtime replicas.
Without persistence, active execution state is held in memory and pod scaling can interrupt work.

=== Workflow Gateway

The gateway Deployment can be targeted by an HPA when `workflowGateway.application.replicas` is
left unset. For this release, set the HPA's `maxReplicas` to `1`: async instance routing state is
held in memory and is not shared between gateway replicas. See
xref:components/workflow-gateway.adoc[Workflow Gateway limitations].

=== Data Index and Vector

The LogicPlatform webhook defaults Data Index to one replica and the operator reconciles the
configured count. No HPA contract is provided for Data Index. Vector is a DaemonSet and is not
scaled through HPA.

== TLS and ingress

The platform can create Ingresses on Kubernetes or Routes on OpenShift for Data Index and the
Workflow Gateway. Configure an explicit host when enabling either ingress. TLS can use a Secret or
cert-manager issuer, but not both. `LogicFlowService` supports Ingress, OpenShift Route, and
Gateway API HTTPRoute modes; review its routing restrictions before choosing a traffic-split
strategy.

== Platform readiness

`LogicPlatform.status.conditions[type=Ready]` is an aggregate of enabled components. A configured
gateway, Data Index, or Vector component that is not ready makes the platform not ready. The
component status fields show which one is still progressing. A configured external ingress host
is not required for the gateway's component readiness condition.

== Operator upgrades

The operator image version and component image versions are separate version streams: operator
`{operator-version}`, Workflow Gateway `{workflow-gateway-version}`, Data Index
`{data-index-version}`, and Quarkus Flow Runner `{quarkus-flow-runner-version}`. The operator build
embeds its default gateway, Data Index, and Quarkus Flow Runner versions. On admission,
LogicPlatform defaults the gateway and Data Index images into the resource spec; those values are
then reconciled as configured and are not automatically advanced when the operator is upgraded.
Review and update these image fields deliberately when upgrading platform components. A
LogicFlowRuntime with an empty image uses the runner version embedded in the current operator, so
upgrading the operator can change the runtime image on its next reconciliation.
