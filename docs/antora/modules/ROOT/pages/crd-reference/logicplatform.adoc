= LogicPlatform CRD Reference
:description: Configure and inspect Data Index, Vector, Workflow Gateway, and runtime defaults through LogicPlatform.

`LogicPlatform` manages namespace-level platform components. A platform can manage Data Index,
Vector log collection, and the Workflow Gateway. `LogicFlowRuntime` resources remain independent
resources; the platform does not create runtimes or workflow definitions.

The operator permits one `LogicPlatform` per namespace. All child Deployments, Services,
DaemonSets, Ingresses or Routes, and gateway RBAC bindings are reconciled in relation to that
resource.

== API Version and Kind

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicPlatform
----

== Spec

=== `dataIndex`

Configures Data Index. `dataIndex.enabled` defaults to `true`. While enabled, Data Index requires
PostgreSQL settings under `dataIndex.persistence.postgresql`; the admission webhook requires a
credential Secret, Kubernetes Service, database name, and database schema. Set
`dataIndex.enabled: false` when you do not want Data Index.

`dataIndex.application` configures the Data Index Deployment. The default image is
`quay.io/kubesmarts/data-index-service:{data-index-version}`. The webhook supplies that image,
one replica, and resource requests and limits when omitted. A user-specified replica count is
reconciled by the operator.

`dataIndex.persistence.postgresql` configures the PostgreSQL connection. The credential Secret
defaults to keys `POSTGRESQL_USER` and `POSTGRESQL_PASSWORD`; `userKey` and `passwordKey` can
select different keys. `serviceRef.port` is optional and defaults to PostgreSQL's port `5432`.
When `serviceRef.namespace` is omitted, the operator uses the service name as a hostname and
Kubernetes DNS search resolves a same-namespace Service. Set `namespace` to build a fully
qualified Service address for a Service in another namespace. The Data Index database name and
schema are required.

`dataIndex.ingress` optionally exposes the GraphQL endpoint through a Kubernetes Ingress or
OpenShift Route. When enabled, `host` is required. TLS can reference an existing Secret or a
cert-manager Issuer, but not both.

=== `dataIndex.vector`

Vector is optional and configured under Data Index. Set `enabled: true` to create its DaemonSet.
The operator supplies the default image and resource requests and limits when omitted. Vector
collects structured workflow logs from host container log files and filters them by namespace.

When `watchNamespaces` is omitted, the webhook sets it to the LogicPlatform's namespace. The
current controller passes only the first entry to Vector as its namespace filter. Use a single
exact namespace name. Although the API type mentions `"*"` and lists, wildcard and multi-namespace
filtering are not implemented: `"*"` is treated as a literal namespace value.

`debugEvents` enables verbose event output to Vector's standard output; leave it disabled outside
troubleshooting because it can produce substantial log volume.

=== `workflowGateway`

Presence of `workflowGateway` enables the Workflow Gateway. The operator creates its Deployment,
ClusterIP Service, ServiceAccount, ClusterRoleBinding, and optional Ingress or OpenShift Route.
Removing the field disables the gateway and cleans up the managed resources.

`workflowGateway.application` accepts the common application settings: `image`, `imagePullPolicy`,
`replicas`, `resources`, `container`, and `podTemplate`. When `image` is omitted, the admission
webhook writes the gateway image version built into the operator into the LogicPlatform spec. The
operator leaves replicas unset by default,
so Kubernetes starts one replica and an HPA can own the scale. Keep `maxReplicas: 1` until the
gateway's in-memory instance routing state is shared; see
xref:components/workflow-gateway.adoc[Workflow Gateway].

`workflowGateway.ingress` is optional. When enabled it requires a `host` and creates an Ingress
on Kubernetes or a Route on OpenShift. The gateway's user API is exposed on Service port 80,
targeting container port 8080. Health and readiness probes use the container's management port
8081.

=== `runtimeDefaults`

The API schema includes `runtimeDefaults` with the same runtime settings as `LogicFlowRuntime`.
The current controller does not apply this field to `LogicFlowRuntime` resources. Configure each
runtime directly until platform-to-runtime default inheritance is implemented.

== Status

Component status fields are siblings under `status`; Vector status is not nested under Data Index.

[source,yaml]
----
status:
  phase: Ready
  observedGeneration: 3
  dataIndex:
    ready: true
    service:
      deploymentRef:
        name: example-data-index
      serviceRef:
        name: example-data-index
      replicas:
        desired: 1
        current: 1
        ready: 1
        updated: 1
      graphqlEndpoint: http://example-data-index.default.svc.cluster.local:80/graphql
      metricsEndpoint: http://example-data-index.default.svc.cluster.local:80/q/metrics
    persistence:
      valid: true
      secretExists: true
      serviceExists: true
  vector:
    ready: true
    daemonSetRef:
      name: example-vector
  workflowGateway:
    ready: true
    deploymentRef:
      name: example-workflow-gateway
    serviceRef:
      name: example-workflow-gateway
    serviceAccountRef:
      name: example-workflow-gateway
    ingressRef:
      name: example-workflow-gateway
    url: http://gateway.example.com
  conditions:
    - type: Ready
      status: "True"
      reason: Ready
      message: All enabled platform components are ready
----

`status.dataIndex.ready`, `status.vector.ready`, and `status.workflowGateway.ready` report the
individual enabled components. Data Index service details are in `status.dataIndex.service`;
Vector and gateway status are top-level siblings. Optional `dataIndex.persistence.databaseConnected`
is populated when a database connection check is available.

`status.conditions` includes component conditions such as `DataIndexReady`,
`DataIndexDeploymentAvailable`, `DataIndexServiceReady`, `DataIndexPersistenceReady`, `VectorReady`,
and `WorkflowGatewayReady`. The aggregate `Ready` condition is true only when every enabled
component is ready. `status.phase` is `Pending`, `Ready`, or `Failed`; a platform with no enabled
components is considered ready.

Data Index Ingress/Route references are at `status.ingressRef` or `status.routeRef`. Gateway
references are nested under `status.workflowGateway`. The gateway URL is populated only when its
Ingress or Route is enabled and has a resolved host.

== Gateway-only example

This configuration is suitable for clusters where workflows are invoked through the gateway but
Data Index and Vector are not enabled:

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicPlatform
metadata:
  name: workflow-platform
  namespace: default
spec:
  dataIndex:
    enabled: false
  workflowGateway:
    ingress:
      enabled: true
      host: gateway.example.com
      ingressClassName: nginx
----

== Full example

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicPlatform
metadata:
  name: workflow-platform
  namespace: workflows
spec:
  dataIndex:
    enabled: true
    persistence:
      postgresql:
        secretRef:
          name: postgres-credentials
        serviceRef:
          name: postgres
          databaseName: logicflow
          databaseSchema: logicflow_dataindex
    vector:
      enabled: true
      watchNamespaces:
        - workflows
  workflowGateway:
    ingress:
      enabled: true
      host: gateway.example.com
      ingressClassName: nginx
----

== Troubleshooting

=== Platform is not ready

Inspect the aggregate `Ready` condition and the enabled component's own `ready` field:

[source,bash]
----
kubectl get logicplatform workflow-platform -o yaml
kubectl describe logicplatform workflow-platform
----

For Data Index, check PostgreSQL Secret and Service references and the generated Deployment.
For Vector, check that the namespace filter matches the workflow namespace and inspect the
DaemonSet pods. For the gateway, check its Deployment, Service, and (when configured) Ingress or
Route. A configured external route is not required for the gateway component's `ready` status.
