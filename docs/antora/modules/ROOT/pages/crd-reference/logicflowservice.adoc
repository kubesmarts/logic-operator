= LogicFlowService
:description: Expose workflow versions through an Ingress, OpenShift Route, or Gateway API HTTPRoute.

`LogicFlowService` provides a stable external endpoint for one workflow identity and its
`LogicFlowDefinition` version or versions. The controller resolves the referenced definitions
and runtime; all referenced definitions must be in the service's namespace, use the same logical
workflow name, and target the same runtime.

== Spec

Set exactly one of `defaultDefinition` or `traffic`.

=== `defaultDefinition`

Routes all requests to one `LogicFlowDefinition`:

[source,yaml]
----
spec:
  defaultDefinition:
    name: hello-world-v1-0-0
----

=== `traffic`

Splits requests among versions. Weights must sum to 100. Kubernetes Ingress mode uses nginx and
supports at most two traffic entries. OpenShift Route traffic splitting requires Gateway API mode.
Gateway API mode requires Gateway API CRDs to be installed in the cluster.

[source,yaml]
----
spec:
  traffic:
    - definitionRef:
        name: order-v1-0-0
      weight: 80
    - definitionRef:
        name: order-v1-1-0
      weight: 20
----

=== `ingress`

Required configuration. The controller creates an Ingress on Kubernetes, a Route on OpenShift,
or an HTTPRoute when `gatewayRef` is set.

`host` is required for Kubernetes Ingress mode unless a Gateway API reference is supplied. The
OpenShift router can assign a host when one is omitted. `ingressClassName` is supported only for
nginx Ingress mode.

`gatewayRef.name` selects a Gateway API `Gateway`; optional `gatewayRef.namespace` defaults to
the LogicFlowService namespace. The presence or absence of `gatewayRef` cannot be changed after
the LogicFlowService is created. Its name and namespace may be updated.

`annotations` are copied to the generated Ingress, Route, or HTTPRoute where supported. TLS can
use either `secretRef` or a cert-manager issuer; the two options are mutually exclusive.

[source,yaml]
----
spec:
  defaultDefinition:
    name: order-v1-0-0
  ingress:
    host: order.example.com
    ingressClassName: nginx
    tls:
      enabled: true
      certManager:
        issuerRef:
          name: letsencrypt-prod
          kind: ClusterIssuer
----

== Status

The controller reports `observedGeneration`, the discovered `runtimeRef`, the created resource
reference (`ingressRef`, `routeRef`, or `httpRouteRef`), the external `url`, and the configured
traffic entries. Each traffic entry's `ready` value reflects whether the shared runtime has ready
replicas; it is not a separate health check for that workflow version.

The controller sets the `IngressReady` condition. It does not currently publish a condition named
`Ready`, even though the CRD's kubectl print-column selector looks for that name. Inspect
`status.conditions[type=IngressReady]` when diagnosing the service.

== Example

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicFlowService
metadata:
  name: order-api
  namespace: default
spec:
  traffic:
    - definitionRef:
        name: order-v1-0-0
      weight: 80
    - definitionRef:
        name: order-v1-1-0
      weight: 20
  ingress:
    host: order.example.com
    ingressClassName: nginx
----
