= ClusterLogicPlatform CRD Reference
:description: Configure the cluster-scoped Logic Platform and its managed services.

`ClusterLogicPlatform` is the cluster-scoped singleton configuration for platform services. It
selects a `targetNamespace` for managed components and can configure Data Index, Workflow Gateway,
Vector, and runtime persistence defaults. The operator accepts one `ClusterLogicPlatform` per
cluster. `LogicFlowRuntime` resources remain namespaced and may run in other namespaces.

== API Version and Kind

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: ClusterLogicPlatform
metadata:
  name: default
spec:
  targetNamespace: logic-platform
----

== Spec

=== `targetNamespace`

Required namespace for platform-managed Deployments, Services, and other namespaced resources.
Create this namespace before applying the resource unless another component (such as the stack
Helm chart) creates it. This field is immutable after creation. To move the platform, delete the
`ClusterLogicPlatform` and recreate it with the new namespace.

[IMPORTANT]
====
Deleting the `ClusterLogicPlatform` removes its managed Data Index, Gateway, and Vector resources.
Cleanup may take time; wait for the platform object to be fully deleted before recreating it. Do
not delete the old target namespace first, because the Gateway finalizer needs it to clean up.

Runtime resources and PostgreSQL databases are not moved or deleted with the platform. Before
recreating it, ensure the new target namespace has the configured PostgreSQL Service and source
credential Secrets. If the database itself is moving, back up and restore its Data Index, runtime,
and Quartz schemas. Runtime credential copies are synced again during reconciliation after the
platform is recreated, provided their referenced source Secrets are available. After recreation,
wait for the platform and runtimes to become ready before removing old database resources.
====

=== `dataIndex`

Presence of `dataIndex` enables Data Index. When enabled, PostgreSQL persistence is required. Set
`dataIndex.persistence.postgresql` with a credentials Secret and Service reference, database name,
and schema. Set `serviceRef.namespace` when PostgreSQL is in a different namespace from
`targetNamespace`; omit it when both resources share a namespace. See the
xref:samples/persistence.adoc[Persistence & Data Index sample].

`dataIndex.application` configures the Deployment. `dataIndex.ingress` optionally exposes the
GraphQL endpoint. When enabled, provide a host.

=== `gateway`

Presence of `gateway` enables the Workflow Gateway. The operator creates its Deployment, Service,
ServiceAccount, ClusterRoleBinding, and optional Ingress or OpenShift Route. `gateway.application`
configures the image and pod; `gateway.ingress` controls external exposure. See
xref:components/workflow-gateway.adoc[Workflow Gateway].

=== `vector`

Presence of `vector` enables the Vector DaemonSet for structured workflow logs. Configure
`vector.watchNamespaces` for the namespace whose runtime logs it should collect. Vector's current
upstream configuration supports a single namespace; configure one exact namespace value.

=== `runtime.persistence`

Optional datastore defaults for runtimes that reference this platform with `spec.platformRef` and
use `spec.persistenceMode: PlatformDB`. Configure `runtime` and `quartz` independently under
`runtime.persistence`. Each datastore has its own PostgreSQL connection and schema settings. See
xref:samples/persistence.adoc[the persistence sample] for the complete YAML.

[[runtime-defaults]]
=== `runtime.defaults`

Optional default deployment settings for runtimes. A `LogicFlowRuntime` inherits them only when it
names the platform with `spec.platformRef.name`; a runtime without a `platformRef` gets no platform
defaults. Precedence is the runtime value, then the platform value, then the operator fallback. A
platform value is never required, and it never causes a runtime to be rejected.

[source,yaml]
----
spec:
  runtime:
    defaults:
      imagePullPolicy: IfNotPresent
      resources:
        requests:
          cpu: 250m
          memory: 512Mi
      container:
        env:
          - name: TZ
            value: UTC
        livenessProbe:
          initialDelaySeconds: 30
      podTemplate:
        metadata:
          labels:
            team: payments
----

Supported fields:

[cols="1,3",options="header"]
|===
|Field |Behavior

|`imagePullPolicy`, `resources`
|Used only when the runtime sets no value in any tier. `resources` is replaced whole: a runtime
that sets any request or limit ignores the platform `resources` entirely.

|`container.env`, `podTemplate.container.env`
|Literal `name` and `value` pairs, merged by name. The runtime wins on a name conflict, and
platform-only variables are added before the runtime ones. `valueFrom` is not supported.

|`container` and `podTemplate.container` probes
|Timings only (`initialDelaySeconds`, `periodSeconds`, `timeoutSeconds`, `failureThreshold`),
applied onto the operator's default probes while keeping their handlers. A probe the runtime
defines wins whole. `startupProbe` affects durable runtimes only.

|`podTemplate.metadata.labels`, `podTemplate.metadata.annotations`
|Merged as maps; the runtime wins on a key conflict. Operator labels (`app.kubernetes.io/name`,
`app.kubernetes.io/managed-by`, `app.kubernetes.io/part-of`) always win over platform and runtime
values.
|===

`image`, `replicas`, and scheduling fields (such as `nodeSelector`, `tolerations`, and `affinity`)
are not supported as defaults. The runner image is always chosen per runtime from its persistence
mode.

[WARNING]
====
Changing a default that alters a runtime's pod template (`env`, `resources`, `imagePullPolicy`,
probe timings, pod labels or annotations) rolls out every inheriting runtime at once. A runtime
that already overrides the field is not restarted. Single-replica runtimes use the `Recreate`
strategy, so they are briefly unavailable during the rollout.

`env` values are visible to anyone who can read the `ClusterLogicPlatform`; do not put credentials
there. A variable whose name the operator sets itself, such as `QUARKUS_DATASOURCE_*` and
`QUARKUS_QUARTZ_*`, is replaced by the operator's value, so setting it has no effect. The only
exception is `QUARKUS_FLOW_DURABLE_KUBE_LEASE_MEMBER_ACQUIRE_TIMEOUT`, which the operator sets only
when no platform or runtime value exists.
====

== Status

Status reports readiness for configured components and includes an aggregate `phase` and
conditions. Component status is exposed under `status.dataIndex`, `status.vector`, and
`status.gateway`.

[source,yaml]
----
status:
  phase: Ready
  dataIndex:
    ready: true
    service:
      graphqlEndpoint: http://data-index.logic-platform.svc.cluster.local:80/graphql
  gateway:
    ready: true
    serviceRef:
      name: default-workflow-gateway
  conditions:
    - type: Ready
      status: "True"
      reason: Ready
      message: All enabled platform components are ready
----

== Minimal gateway-only example

Data Index and Vector remain disabled when omitted. This is the same simple platform used by the
hello-world sample; no persistence database is required.

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: ClusterLogicPlatform
metadata:
  name: default
spec:
  targetNamespace: logic-platform
  gateway: {}
----

== Troubleshooting

Inspect the aggregate condition and the affected component status:

[source,bash]
----
kubectl get clusterlogicplatform default -o yaml
kubectl describe clusterlogicplatform default
----

For Data Index, verify its PostgreSQL Secret and Service references and inspect the generated
Deployment. For Vector, verify the configured namespace matches the runtime namespace. For the
gateway, inspect its Deployment, Service, and optional Ingress or Route.
