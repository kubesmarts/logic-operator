= Hello World Sample
:description: End-to-end walkthrough of the hello-world workflow using make kind-demo.

The hello-world sample is the quickest way to see Logic Operator in action.
It deploys a LogicPlatform-managed gateway, a stateless runtime, and a single-step workflow. The gateway Ingress is the public endpoint.

== Prerequisites

A running KIND cluster with the operator deployed. If you have not done this yet, follow xref:deployment/kind-local.adoc[Local Development with KIND].

== Apply the Sample

[source,bash]
----
make kind-demo
----

This builds and loads the gateway image, then applies `config/samples/`, which creates a `LogicPlatform`, `LogicFlowRuntime`, and `LogicFlowDefinition`.

== The Custom Resources

=== LogicFlowRuntime

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicFlowRuntime
metadata:
  name: hello-runtime
spec: {}
----

An empty `spec` means the operator uses all defaults: one replica of the operator's Quarkus Flow Runner image (`{quarkus-flow-runner-version}-minimal` in this release), no persistence, and no authentication.
The operator creates a `Deployment` and `Service` named `hello-runtime`.

=== LogicFlowDefinition

[source,yaml]
----
apiVersion: logic.kubesmarts.org/v1
kind: LogicFlowDefinition
metadata:
  name: hello-world-v1-0-0
spec:
  runtimeRef:
    name: hello-runtime
  flow:
    document:
      dsl: '1.0.0'
      namespace: examples
      name: hello-world
      version: '1.0.0'
    do:
      - greet:
          set:
            message: '${ "Hi, " + .name + "!" }'
----

This is an OWS 1.0.0 document.
The single task `greet` uses a `set` action to build the response string from the input field `.name`.
The operator propagates this definition as a ConfigMap into the runtime pod.

The `LogicPlatform` sample enables its workflow gateway with an Ingress at `gateway.lvh.me`. The gateway maps the workflow identity from the definition labels to `spec.runtimeRef.name`, then calls the runtime's Kubernetes Service. No `LogicFlowService` is required for this route. If a matching `LogicFlowService` exists, the gateway prefers its `status.url`.

== Wait for the Runtime

[source,bash]
----
kubectl wait --for=condition=available deployment/hello-runtime --timeout=120s
kubectl wait --for=condition=available deployment/logicplatform-sample-workflow-gateway --timeout=120s
----

Check the platform, runtime, and definition:

[source,bash]
----
kubectl get logicplatforms,logicflowruntimes,logicflowdefinitions
----

== Invoke the Workflow

[source,bash]
----
curl -X POST http://gateway.lvh.me/v1/runtime/default/hello-world/1.0.0/sync \
  -H "Content-Type: application/json" \
  -d '{"name": "World"}'
----

Expected response:

[source,json]
----
{"message": "Hi, World!"}
----

[TIP]
====
`gateway.lvh.me` resolves to `127.0.0.1` via public DNS.
No `/etc/hosts` changes are needed.
====

== Check Health

[source,bash]
----
kubectl port-forward svc/hello-runtime 8080:80
----

Then query it:

[source,bash]
----
curl http://localhost:8080/q/health
----

The response shows liveness and readiness probes from the Quarkus SmallRye Health extension.

== Check Metrics

[source,bash]
----
curl http://localhost:8080/q/metrics
----

After invoking the workflow once, look for:

[source]
----
quarkus_flow_workflow_started_total{workflow="hello-world"} 1.0
quarkus_flow_workflow_completed_total{workflow="hello-world"} 1.0
----

== Explore the OpenAPI Spec

[source,bash]
----
curl http://localhost:8080/q/openapi
----

The Quarkus Flow Runner generates an OpenAPI spec that includes all loaded workflow definitions.

== Clean Up

[source,bash]
----
make kind-undemo
----
